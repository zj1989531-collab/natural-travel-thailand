# 票务盈利簿

面向手机的个人出票盈利统计工具。先维护供货商的项目、可选子项/套餐、成本与代理售价；出票时选择项目自动带入价格，并统计今日、本月及供货商利润排行。没有套餐区分时，子项可留空，系统会显示为“不分套餐”。

## 启动

需要 Node.js 22+ 与 pnpm：

```bash
pnpm install
pnpm dev
```

访问终端显示的本地地址后，可通过手机浏览器的“添加到主屏幕”安装。生产构建使用 `pnpm build`。

## GitHub 自动部署

目标仓库：[natural-travel-thailand](https://github.com/zj1989531-collab/natural-travel-thailand)。
线上地址：[票务盈利簿](https://zj1989531-collab.github.io/natural-travel-thailand/)。

在仓库 Settings → Pages 将 Source 设为 GitHub Actions。每次推送 main，工作流会安装固定版本依赖、运行测试、构建并发布；失败的检查不会更新线上网站。Pages 项目路径和手机离线资源在构建时自动适配，打开或刷新线上页面可获得最新版本。

本机先运行 `pnpm github:login`，按提示完成 GitHub Git 登录，然后可以运行：

```bash
pnpm dev:sync
```

它同时打开本地开发服务并监听源码：保存后等待 5 秒，测试和构建通过才自动提交、上传。保持这个终端运行；关闭终端或 Ctrl+C 会停止监听。仅需后台监听可运行 `pnpm sync:watch`，单次上传可运行 `pnpm sync:github`。普通 `pnpm dev` 只启动网站，不上传代码。

自动上传限定为应用源码和部署配置，不会上传浏览器账本、Excel 备份或 `.env.local`。检测到手动暂存、远程新提交或检查失败时会暂停该次上传；不会强制覆盖远程修改。若 GitHub 登录失效，请重新完成本机 Git 登录。

完整的首次设置步骤见 [DEPLOYMENT.md](./DEPLOYMENT.md)。

## 启用云端同步

1. 新建一个 Supabase 项目。安装 Supabase CLI 后，在本地或临时环境运行 `supabase init`、`supabase start` 和 `supabase db reset`，由 [supabase/migrations](./supabase/migrations/) 的时间戳链创建完整结构。不要再按根目录 SQL 文件的名称手工猜测执行顺序；已有生产库的安全升级流程见 [supabase/MIGRATIONS.md](./supabase/MIGRATIONS.md)。
2. 在 Authentication 中启用 Email / Magic Link，并把应用地址加入 Redirect URLs。若启用密码登录，同时在 Authentication → Password Security 开启“Prevent use of leaked passwords”（该能力需要 Supabase Pro 或更高套餐）。
3. 复制 `.env.example` 为 `.env.local`，填写项目 URL 与 publishable key 或 anon key。
4. 重启开发服务；登录邮箱后，本机尚未同步的记录会归属到该账号并自动上传。

个人首次使用可先用注册 Supabase 时的邮箱登录。默认发信服务只允许组织成员的邮箱；其他邮箱需先配置自己的 SMTP 服务。两台设备应始终使用同一个邮箱，避免建立两个不同的账本账号。

不配置 Supabase 时，应用仍可离线使用并将数据保存在当前浏览器。清除浏览器网站数据会清除仅本机数据，因此应定期导出 Excel。

线上构建在 GitHub 仓库的 Settings → Secrets and variables → Actions 配置 `VITE_SUPABASE_URL` 和 `VITE_SUPABASE_ANON_KEY`，然后重新运行 Deploy ticket ledger。两端登录同一邮箱，在线修改会自动同步；离线修改会排队，联网后自动上传。页面恢复前台时会重新核对数据，另有定时重试。GitHub Pages 发布会强制检查这两个值；缺少任意一个会停止发布，避免误发布成仅本机账本。本地 `pnpm build` 仍可不配置 Supabase，用于离线账本开发与验收。

已有数据库使用 `supabase migration list` 先核对历史版本，再按 [supabase/MIGRATIONS.md](./supabase/MIGRATIONS.md) 在临时副本完成 `supabase db push --dry-run` 和回归验证。不得对生产库重跑基线、历史 no-op 标记或根目录兼容脚本；生产库只会接收晚于其已记录版本的新迁移。电脑与手机都应在前端发布后刷新到新版。

现有云端的供货商名称更正已执行 [supabase/canonical-supplier-brand.sql](./supabase/canonical-supplier-brand.sql)，同步更新供货商、套餐及历史票据名称，并兼容旧客户端拼写。该脚本用于已有业务数据，需在退款相关脚本之后执行；详见 [部署说明](./DEPLOYMENT.md#供货商名称更正)。

套餐可设置默认按人／件或整单计价，以及日结／月结。旧套餐按名称推荐默认值，保存设置后固定；每次出票可临时改计价，历史记录保留自身金额与结算归属。保存前会合并提示本机缓存中疑似重复或亏损的记录，确认后仍可保存；离线提示不能保证发现另一设备尚未同步的重复业务。

项目可勾选成本、售价每次手填，并可选择不预设供货商。此类套餐在每次选择后清空价格和供货商，保存实际记录时必须填写金额并选择本账号已有供货商；历史记录保留实际金额和供货商。叫车按整单计价、整单统计，不重复乘人数。旧客户端缺少新字段时不会清空云端手填规则，升级后电脑和手机均需刷新。

新增订单的保存重试复用同一提交记录，已保存但页面刷新失败时会明确提示已保存。切换账号先隔离本机账本，退出后锁定缓存，重新登录对应账号再查看。同步先核对退票，单笔确定性拒绝不阻塞其他正常订单；多设备编辑冲突会保留本机修改副本并采用云端订单，可从“同步记录核对”查看差异、复制本机内容、标记已核对及查看处理历史。冲突副本仅保留在当前设备；标记不会自动覆盖云端。未被云端接受且未再编辑、无退票历史的错误草稿核对后会从活动账本移除，副本仍保留。

退票提交中禁止修改内容、关闭窗口或操作背景页面。退票和79秀分账一旦提交，会在当前设备按账号保留原内容及提交编号；结果待确认时锁定原内容，切换页面、月份或重新打开后，仍先核对／重试原笔。确认保存后才清理待核对提交，再允许登记新业务；分账明确因快照冲突被拒绝时，可按刷新后的金额重新核对。此处只保留已发出的财务请求，不自动保存尚未提交的普通录入草稿。清除浏览器资料仍会删除本机待核对信息。

自动填写支持国际姓名，不把姓名内的“VIP”片段当作套餐；未识别姓名时清空上一姓名并提示核对。超过50人的自动填入会显示自定义人数。Excel保留原计价人数，只有有效出票记录计入有效人数／件数；出票与退票表通过内部原票编号关联，退票明细提供客户、项目、套餐和人数／件数，79秀退票继续独立导出。内部关联编号不会出现在客户确认单上。

退票按客户姓名、项目、日期等查找，并在原票摘要和最终确认核对客户。退款日期记录实际退款日，可早于观看／出行日期，不得晚于曼谷今天；利润与有效人数仍回算原票所属日期和月份。旧版已存的未来退款日期不批改，仍可撤销。

首页“利润走势与对比”支持当前及历史月份，分别显示每日的日结、月结利润（非累计），与主账本一样不含69秀、79秀、泰拳、格兰岛一日游及东方嘉年华独立账本。本月仅统计到曼谷今天，与上月同期比较；上月天数不足时取月底。历史月份按整月比较。月结金额按出票日期归属，不表示已到账；退票仍回算原出票日期。上期利润为零、亏损或无记录时只展示差额，不展示增长率。支持点击图表日期、下拉选日及展开每日明细；离线从本机数据计算，无需新增数据库配置。

## 药品多项录入

新增记录选择“药品”后，可同时勾选男款、女款等多个子项。客户、日期、时间和备注共用；每项分别填写件数、售价和成本，成本从各自价格表带入，需要手填的售价不猜测为零。页面显示各项利润和合计，任一项未填完整时不能保存。一次保存全部药品明细，失败重试复用本次提交，避免重复记录；各项继续按独立商品明细查找、修改、退货和导出，不计入门票人数。

## 79秀独立账本

底部“79秀”入口独立显示所选日期人数、月人数、月实际利润和订单明细。79秀不计入主账本的日报、月报、年报、累计报表、供货商排行及普通 Excel 导出；完整 JSON 备份仍包含79秀订单。历史79秀、79成人秀与全角名称也自动归入独立账本。

按实际净利润计算 jimmy 40%、大狗二狗合计60%，不是固定每人50泰铢。月利润先按分汇总，再统一分账；尾差计入大狗二狗，确保总额一致。保留原退票规则：退票人数及净利润回算原记录日期和月份；历史未录人数会提示，不猜测人数。仅录利润的返佣记录保留利润，不当作入场人数。

在79秀页面输入“79 jimmy 2人 今天”或“李湘光 龙粉萍 今天 2个79”可填入姓名、曼谷日期和人数，支持人数单位“人、个、位、名、张”及前后放置79，按钮“黏贴/自动填入”会读取剪贴板文字并立即识别，按钮旁显示结果或错误；首次使用可能需要允许浏览器黏贴，不支持时可长按输入框黏贴后自动识别，也可用“识别当前文字”处理手动输入；核对后生成固定模板的 PNG 图片，日期使用 YYYY/MM/DD，预订单号留空。可点击“复制图片（无需保存）”把 PNG 图片内容写入剪贴板，再切换微信尝试在聊天输入框粘贴；是否支持图片粘贴取决于手机与微信。也可下载、打印保存 PDF，或在支持文件分享的手机浏览器调用系统分享菜单选择微信。确认单不展示成本、利润、分成或内部备注。仅生成图片不会创建记账记录或向供应商下单。“保存并生成确认单”先记账再生成图片；图片生成失败时可以只重试生成，避免重复保存。预览明确标注是否已记账，从订单生成的图片关联原票与退票版本，修改、退款、撤销、删除或同步变动后旧预览失效，须重新生成；已发出的外部图片不在系统控制范围内。

保存订单时选择已有79秀供货商套餐并填写实际金额；新订单按所填观看日期保存到独立账本（历史订单日期不变）。月底可导出包含订单和40%/60%分成的独立 Excel。分账报表随订单修改和退票重新计算，导出文件可作为当次核对凭据，不会自动付款。

## 格兰岛一日游与东方嘉年华独立账本

底部“月结票”中的格兰岛一日游和东方嘉年华均为独立账本：订单在各自页面录入、查询、编辑、退票和撤销退票，不计入主账本日报、月报、年报、利润走势、供货商排行、格式化报表或普通 Excel 导出。完整 JSON 备份和云端同步仍保留全部订单与退票，已有历史订单会自动归入对应独立账本。

两者都必须从价格表选择按人数、月结的有效套餐；保存时会冻结套餐、价格与曼谷时间，重试不会读取后续改价。它们不继承79秀的40%/60%分账或确认单逻辑，也无需新增 Supabase 表或执行数据库迁移。

## 功能边界

第一版不包含真实出票、多币种、客户/乘客资料、应收应付、员工协作或历史数据导入。

Excel 功能仅将账本数据生成下载文件，不读取、导入或解析外部工作簿。任何未来的 Excel 导入功能都必须先完成依赖安全升级与专项安全审查；测试会阻止在当前代码中加入 SheetJS 读取／解析 API。
